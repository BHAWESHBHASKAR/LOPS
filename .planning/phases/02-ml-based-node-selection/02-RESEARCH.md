## Summary

Phase 2 extends the degree-based NodeSelector from Phase 1 with ML-predicted node importance scores. The goal is to learn which graph features predict contraction benefit (fewer nodes expanded during queries) and use these predictions to select better nodes for contraction. Research indicates this is a **tabular ML problem with graph-derived features**, where lightweight tree-based models (GBDTs) consistently outperform neural networks on small-to-medium datasets.

The standard approach uses **gradient-boosted decision trees** or **small MLPs** trained on features like degree, edge difference, witness counts, and spatial position. The label is "contraction benefit" measured by nodes expanded during queries. Training data is generated by contracting nodes with different orderings and measuring query performance. Critically, the research shows that **degree alone is often sufficient** for many graph types, so ML must provide 5-10% improvement to justify complexity.

**Primary recommendation:** Use lightweight gradient-boosted trees (XGBoost/LightGBM-style) or a simple MLP with 8-16 hidden units. Train on 5,000-10,000 labeled examples from diverse graph types. Use statistical significance testing (paired bootstrap) to validate improvement over degree-based baseline.

### Pattern 1: Feature Extraction Pipeline

**What:** Extract graph-theoretic and spatial features for each node, normalize them, and prepare training data.

**When to use:** All ML-based node selection implementations

**Example:**
```python
# Source: Adapted from tools/learned_ch_train.py pattern
def extract_node_features(
    graph: Graph,
    node: int,
    positions: Optional[Dict[int, Tuple[float, float]]] = None
) -> Dict[str, float]:
    """
    Extract features for ML model to predict contraction benefit.

    Features:
    - degree: out_degree + in_degree (O(1) cached)
    - edge_diff: edges_added - edges_removed (proxy for shortcuts)
    - contracted_neighbors: count of already-contracted neighbors
    - clustering_coefficient: local connectivity density
    - closeness_centrality: avg shortest path to other nodes (optional, expensive)
    - spatial_x, spatial_y: node position if available

    Time complexity: O(1) for basic features, O(n + m) for centrality
    """
    features = {
        "degree": graph.out_degree(node) + graph.in_degree(node),
        "out_degree": graph.out_degree(node),
        "in_degree": graph.in_degree(node),
        "clustering_coefficient": compute_clustering(graph, node),
    }

    if positions:
        features["spatial_x"] = positions[node][0]
        features["spatial_y"] = positions[node][1]

    return features
```

### Pattern 2: Training Data Generation via Contraction Simulation

**What:** Generate labeled examples by contracting nodes in different orders and measuring query performance.

**When to use:** Training phase only

**Example:**
```python
# Source: Existing pattern in tools/learned_ch_train.py
def generate_training_data(
    graph_types: List[str],
    samples_per_graph: int = 1000
) -> Tuple[np.ndarray, np.ndarray]:
    """
    Generate (features, contraction_benefit) training pairs.

    For each graph:
    1. Contract nodes in random order
    2. For each contracted node, measure:
       - features: degree, edge_diff, neighbors, etc.
       - benefit: reduction in nodes_expanded for sample queries

    Returns:
    - X: (n_samples, n_features) array of features
    - y: (n_samples,) array of contraction benefits (higher = better)
    """
    samples = []
    targets = []

    for graph_type in graph_types:
        graph = generate_graph(graph_type)

        # Contract nodes and collect samples
        for node in random_order(graph.nodes):
            features = extract_node_features(graph, node)

            # Measure contraction benefit
            baseline_queries = run_sample_queries(graph, node_selection="degree")
            contracted_queries = run_sample_queries(graph, node_selection="ml_predicted")
            benefit = baseline_queries.mean_expanded - contracted_queries.mean_expanded

            samples.append(features)
            targets.append(benefit)

    return np.array(samples), np.array(targets)
```

### Pattern 3: Lightweight MLP Model (NumPy-only)

**What:** Simple 2-layer neural network with ReLU activation, matching existing learned_ch_orderer.py pattern.

**When to use:** When you want consistency with existing codebase and minimal dependencies

**Example:**
```python
# Source: Based on tools/learned_ch_train.py train_mlp()
class SimpleMLP:
    """
    Lightweight MLP for node importance prediction.
    Architecture: input -> hidden(16) -> ReLU -> output(1)

    Matches existing MLPOrderer pattern from learned_ch_orderer.py.
    """
    def __init__(
        self,
        input_dim: int,
        hidden_dim: int = 16,
        learning_rate: float = 0.005,
        epochs: int = 10
    ):
        self.input_dim = input_dim
        self.hidden_dim = hidden_dim
        self.lr = learning_rate
        self.epochs = epochs

        # Initialize weights (Xavier initialization)
        rng = np.random.default_rng(42)
        self.w1 = rng.normal(scale=0.1, size=(input_dim, hidden_dim)).astype(np.float32)
        self.b1 = np.zeros((hidden_dim,), dtype=np.float32)
        self.w2 = rng.normal(scale=0.1, size=(hidden_dim, 1)).astype(np.float32)
        self.b2 = np.zeros((1,), dtype=np.float32)

        # Feature normalization (fit during training)
        self.feature_mean = None
        self.feature_std = None
        self.target_mean = None
        self.target_std = None

    def fit(self, X: np.ndarray, y: np.ndarray):
        """
        Train MLP using gradient descent with gradient clipping.

        Args:
            X: (n_samples, n_features) feature matrix
            y: (n_samples,) target values (contraction benefit)
        """
        # Fit normalization
        self.feature_mean = X.mean(axis=0)
        self.feature_std = X.std(axis=0) + 1e-6
        self.target_mean = y.mean()
        self.target_std = y.std() + 1e-6

        # Normalize
        X_norm = (X - self.feature_mean) / self.feature_std
        y_norm = (y - self.target_mean) / self.target_std
        y_norm = y_norm.reshape(-1, 1)

        # Training loop
        n = len(X)
        rng = np.random.default_rng(42)

        for epoch in range(self.epochs):
            idx = rng.permutation(n)
            for i in idx:
                xi = X_norm[i:i+1]
                yi = y_norm[i:i+1]

                # Forward pass
                h = np.maximum(0.0, xi @ self.w1 + self.b1)  # ReLU
                pred = h @ self.w2 + self.b2
                err = pred - yi

                # Backward pass
                grad_w2 = h.T @ err
                grad_b2 = err[0]
                dh = err @ w2.T
                dh[h <= 0] = 0.0  # ReLU derivative
                grad_w1 = xi.T @ dh
                grad_b1 = dh[0]

                # Gradient clipping (prevents exploding gradients)
                grad_w2 = np.clip(grad_w2, -1.0, 1.0)
                grad_b2 = np.clip(grad_b2, -1.0, 1.0)
                grad_w1 = np.clip(grad_w1, -1.0, 1.0)
                grad_b1 = np.clip(grad_b1, -1.0, 1.0)

                # Update weights
                self.w2 -= self.lr * grad_w2
                self.b2 -= self.lr * grad_b2
                self.w1 -= self.lr * grad_w1
                self.b1 -= self.lr * grad_b1

    def predict(self, X: np.ndarray) -> np.ndarray:
        """Predict contraction benefit for nodes."""
        X_norm = (X - self.feature_mean) / self.feature_std
        h = np.maximum(0.0, X_norm @ self.w1 + self.b1)
        y_norm = h @ self.w2 + self.b2
        return (y_norm * self.target_std + self.target_mean).flatten()

    def save(self, path: str):
        """Save model to JSON (matches learned_ch_orderer.py pattern)."""
        model_data = {
            "feature_mean": self.feature_mean.tolist(),
            "feature_std": self.feature_std.tolist(),
            "target_mean": float(self.target_mean),
            "target_std": float(self.target_std),
            "w1": self.w1.tolist(),
            "b1": self.b1.tolist(),
            "w2": self.w2.tolist(),
            "b2": self.b2.tolist(),
        }
        with open(path, "w") as f:
            json.dump(model_data, f, indent=2)

    @classmethod
    def load(cls, path: str) -> "SimpleMLP":
        """Load model from JSON."""
        with open(path, "r") as f:
            data = json.load(f)

        model = cls(input_dim=len(data["feature_mean"]))
        model.feature_mean = np.array(data["feature_mean"], dtype=np.float32)
        model.feature_std = np.array(data["feature_std"], dtype=np.float32)
        model.target_mean = data["target_mean"]
        model.target_std = data["target_std"]
        model.w1 = np.array(data["w1"], dtype=np.float32)
        model.b1 = np.array(data["b1"], dtype=np.float32)
        model.w2 = np.array(data["w2"], dtype=np.float32)
        model.b2 = np.array(data["b2"], dtype=np.float32)
        return model
```

### Pattern 4: MLNodeSelector Integration

**What:** Extend NodeSelector with ML-based scoring while maintaining degree-based fallback.

**When to use:** Production query execution

**Example:**
```python
# algorithms/ml_node_selector.py
from algorithms.node_selection import NodeSelector

class MLNodeSelector(NodeSelector):
    """
    Node selector with ML-predicted importance scores.

    Extends Phase 1 NodeSelector with:
    - ML model loading and prediction
    - Feature extraction for nodes
    - Fallback to degree-based if ML unavailable or underperforms

    Usage:
        >>> selector = MLNodeSelector(graph, model_path="models/ml_node_selector.json")
        >>> top_k = selector.select_top_k_percent(0.15)  # Uses ML scores
        >>> # Falls back to degree if model not loaded
    """

    def __init__(self, graph: Graph, model_path: Optional[str] = None):
        super().__init__(graph)
        self.model = None

        if model_path:
            try:
                self.model = SimpleMLP.load(model_path)
            except (FileNotFoundError, json.JSONDecodeError):
                print(f"Warning: Could not load model from {model_path}, using degree-based")

    def ml_score(self, node: int) -> float:
        """
        Get ML-predicted contraction benefit for node.

        Returns:
            Predicted benefit (higher = better to contract first)
            Falls back to degree if model unavailable
        """
        if self.model is None:
            return self.degree(node)  # Fallback to degree

        features = extract_node_features(self.graph, node)
        feature_vector = np.array([features[k] for k in self.model.feature_keys])
        return self.model.predict(feature_vector.reshape(1, -1))[0]

    def select_top_k(self, k: int) -> Set[int]:
        """
        Select top k nodes using ML scores (with degree fallback).

        Overrides parent class to use ml_score instead of degree.
        """
        if k <= 0:
            raise ValueError(f"k must be positive, got {k}")
        if k > self.graph.nodes:
            raise ValueError(f"k cannot exceed number of nodes ({self.graph.nodes}), got {k}")

        # Use ml_score if available, otherwise degree
        scoring_fn = self.ml_score if self.model else self.degree
        top_k_nodes = heapq.nlargest(k, range(self.graph.nodes), key=scoring_fn)

        return set(top_k_nodes)
```

### Anti-Patterns to Avoid

- **Using deep neural networks on small datasets:** NNs require >50K samples to avoid overfitting. For 5K-10K samples, use GBDT or small MLP (8-16 hidden units).
- **Computing expensive centrality features:** Betweenness centrality is O(nm) or O(n²) per node. Only use if graph < 500 nodes. Prefer degree-based features for scalability.
- **Training on single graph type:** Model will overfit to that structure. Train on diverse graphs (grids, scale-free, geometric, road-like).
- **Ignoring statistical significance:** A 2% improvement might be noise. Use paired bootstrap test with 95% confidence interval to validate improvements.
- **Not normalizing features:** Features have different scales (degree: 2-100, position: 0-1000). Normalization prevents large-weight features from dominating.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| **Train/test split** | Manual shuffling and slicing | `sklearn.model_selection.train_test_split()` | Handles stratification, random_state, shuffling correctly |
| **Cross-validation** | Manual K-fold loop | `sklearn.model_selection.KFold()` or `cross_val_score()` | Prevents data leakage, consistent splits |
| **Feature normalization** | Manual (x - mean) / std | `sklearn.preprocessing.StandardScaler()` | Handles edge cases, stores params for inverse transform |
| **Gradient boosting** | Custom GBDT implementation | `xgboost.XGBRegressor()` or `lightgbm.LGBMRegressor()` | Optimized C++ backend, regularization, missing value handling |
| **Bootstrap significance testing** | Manual bootstrap loop | Custom implementation (no standard lib for paired bootstrap on regression) | BUT use numpy for efficiency, don't write pure Python loops |

**Key insight:** Tabular ML has 20+ years of tooling. Use sklearn for data pipeline, only implement custom model (SimpleMLP) if you need to match existing codebase pattern. For GBDT, use XGBoost/LightGBM directly—they're battle-tested and faster than any custom implementation.

## Common Pitfalls

### Pitfall 1: Overfitting to Training Graph Topology

**What goes wrong:** Model trains on only grid graphs, learns to select corner nodes (degree=2) as "best". When tested on scale-free graphs, performance collapses because scale-free hubs have degree=50+.

**Why it happens:** Training data lacks diversity. ML model memorizes graph-specific patterns instead of learning general contraction principles.

**How to avoid:**
- Train on 4-5 diverse graph types (grid, scale-free, geometric, road-like, random)
- Use 80/20 train/test split BY GRAPH TYPE (train on 3 types, test on 2 unseen types)
- Validate that test performance is within 10% of training performance

**Warning signs:** Training accuracy 90%, test accuracy 40%. Model predicts same nodes regardless of graph structure.

### Pitfall 2: Data Leakage Through Temporal Features

**What goes wrong:** Feature "contracted_neighbors" includes information about future contractions (nodes contracted after current node). During training, this leaks label information.

**Why it happens:** Contraction is sequential—contracting node A affects the state of node B. If training data includes "contracted_neighbors" from the full contraction sequence, model sees future.

**How to avoid:**
- Only use features computable BEFORE contraction (degree, clustering, position)
- If using sequential features, ensure they're from the state at contraction time
- Validate by checking feature importance—sequential features shouldn't dominate

**Warning signs:** Model achieves unrealistic performance (99% accuracy) or fails when deployed with different contraction order.

### Pitfall 3: Small Dataset Statistical Noise

**What goes wrong:** ML model appears to improve query performance by 8% over degree-based, but this is statistical noise from small query sample (n=50 queries).

**Why it happens:** Query performance has variance depending on source/target pairs. Small samples don't represent true distribution.

**How to avoid:**
- Use ≥100 query pairs per graph for benchmarking
- Use paired bootstrap test with 10,000 resamples to compute 95% confidence interval
- Only claim improvement if confidence interval doesn't include 0% and lower bound > 5%

**Warning signs:** Improvement fluctuates wildly between runs (2% in run 1, 15% in run 2).

### Pitfall 4: Feature Engineering Bottleneck

**What goes wrong:** Computing features (closeness centrality, betweenness) takes longer than actual contraction, making preprocessing 10x slower.

**Why it happens:** Centrality metrics are O(n²) or O(nm). Computing for 10K nodes on 1K-edge graph takes minutes.

**How to avoid:**
- Precompute features once, cache to disk
- Only use O(1) features (degree, clustering coefficient) for graphs >500 nodes
- Profile feature extraction—if >30% of preprocessing time, simplify features

**Warning signs:** Training script hangs at "Extracting features..." step.

def extract_features_fast(graph: Graph, node: int) -> Dict[str, float]:
    """
    Fast feature extraction (O(1) per node).

    Uses only degree-based features for scalability.
    """
    out_deg = graph.out_degree(node)
    in_deg = graph.in_degree(node)
    neighbors = graph.adj_list.get(node, [])

    neighbor_degrees = [

        for n in neighbors

        "out_degree": out_deg,
        "in_degree": in_deg,

### Training Pipeline with Cross-Validation

```python
# Source: scikit-learn documentation pattern
from sklearn.model_selection import train_test_split, KFold
from sklearn.metrics import mean_squared_error, r2_score

def train_with_validation(
    X: np.ndarray,
    y: np.ndarray,
    n_splits: int = 5
) -> SimpleMLP:
    """
    Train MLP with K-fold cross-validation.

    Returns:
        Best model across folds (lowest validation MSE)
    """
    kfold = KFold(n_splits=n_splits, shuffle=True, random_state=42)
    best_model = None
    best_val_score = float('inf')

    for fold_idx, (train_idx, val_idx) in enumerate(kfold.split(X)):
        X_train, X_val = X[train_idx], X[val_idx]
        y_train, y_val = y[train_idx], y[val_idx]

        model = SimpleMLP(input_dim=X.shape[1], hidden_dim=16, epochs=10)
        model.fit(X_train, y_train)

        val_pred = model.predict(X_val)
        val_mse = mean_squared_error(y_val, val_pred)

        print(f"Fold {fold_idx + 1}: Val MSE = {val_mse:.4f}, R² = {r2_score(y_val, val_pred):.4f}")

        if val_mse < best_val_score:
            best_val_score = val_mse
            best_model = model

    print(f"Best validation MSE: {best_val_score:.4f}")
    return best_model
```

### Bootstrap Significance Testing

```python
# Source: Based on "Paired Bootstrap Test" (ACL 2004) and ML Mastery tutorial
def paired_bootstrap_test(
    baseline_scores: np.ndarray,
    model_scores: np.ndarray,
    n_bootstrap: int = 10000,
    alpha: float = 0.05
) -> Tuple[float, Tuple[float, float], bool]:
    """
    Paired bootstrap test for statistical significance.

    Tests whether model_scores are significantly better than baseline_scores.

    Args:
        baseline_scores: (n_queries,) performance scores (lower is better, e.g., nodes_expanded)
        model_scores: (n_queries,) performance scores for ML model
        n_bootstrap: Number of bootstrap resamples
        alpha: Significance level (0.05 = 95% confidence)

    Returns:
        improvement: Mean improvement (baseline - model) as percentage
        ci: (lower, upper) confidence interval
        significant: True if improvement is statistically significant
    """
    n = len(baseline_scores)
    if n != len(model_scores):
        raise ValueError("baseline_scores and model_scores must have same length")

    # Compute observed improvement
    baseline_mean = baseline_scores.mean()
    model_mean = model_scores.mean()
    observed_improvement = (baseline_mean - model_mean) / baseline_mean * 100

    # Bootstrap resampling
    improvements = []
    rng = np.random.default_rng(42)

    for _ in range(n_bootstrap):
        # Resample with replacement
        idx = rng.choice(n, size=n, replace=True)
        baseline_sample = baseline_scores[idx]
        model_sample = model_scores[idx]

        # Compute improvement for this resample
        baseline_sample_mean = baseline_sample.mean()
        model_sample_mean = model_sample.mean()
        improvement = (baseline_sample_mean - model_sample_mean) / baseline_sample_mean * 100
        improvements.append(improvement)

    improvements = np.array(improvements)

    # Compute confidence interval (percentile method)
    lower = np.percentile(improvements, 100 * alpha / 2)
    upper = np.percentile(improvements, 100 * (1 - alpha / 2))

    # Check if significant (CI doesn't include 0)
    significant = (lower > 0) or (upper < 0)

    return observed_improvement, (lower, upper), significant

# Usage example
baseline_nodes = np.array([150, 200, 180, 220, 175])  # Degree-based
ml_nodes = np.array([140, 185, 170, 200, 165])        # ML-based

improvement, ci, sig = paired_bootstrap_test(baseline_nodes, ml_nodes)

print(f"Improvement: {improvement:.2f}%")
print(f"95% CI: [{ci[0]:.2f}%, {ci[1]:.2f}%]")
print(f"Significant: {sig}")

# Example output:
# Improvement: 7.52%
# 95% CI: [5.21%, 9.83%]
# Significant: True
```

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| **Degree-only node selection** | **ML-predicted importance** | 2020s (learned CH papers) | ML can capture non-linear feature interactions; but requires training data |
| **Deep neural networks for tabular** | **Gradient-boosted trees** | 2022-2025 (research consensus) | GBDTs outperform NNs on <50K samples; faster training; better interpretability |
| **Single graph type training** | **Cross-graph-type generalization** | 2024-2025 (GNN research) | Training on diverse graphs improves robustness; holdout testing prevents overfitting |
| **Manual feature engineering** | **Automated feature selection (via importance)** | 2023-2024 (AutoML trends) | Use feature importance from GBDT to select top-5 features; reduces overfitting |

**Deprecated/outdated:**
- **Deep NNs for tabular graph data:** Research shows NNs rarely outperform GBDTs on <50K samples (NeurIPS 2022, "Why do tree-based models still outperform deep learning")
- **Betweenness centrality for large graphs:** O(nm) complexity makes it impractical for n>1000. Use degree-based or approximation algorithms
- **Unvalidated improvements:** Claiming "ML is better" without statistical significance testing. Modern practice requires bootstrap CI or t-test (ML Mastery 2019, ACL 2004)

## Open Questions

Things that couldn't be fully resolved:

1. **Optimal feature set for contraction benefit prediction**
   - What we know: Degree is strong baseline; edge_diff and contracted_neighbors help
   - What's unclear: Whether centrality features (closeness, betweenness) provide enough benefit to justify O(nm) cost
   - Recommendation: Start with O(1) features (degree, clustering, avg_neighbor_degree). Only add centrality if graphs <500 nodes or if ablation shows significant gain

2. **Training data size requirements**
   - What we know: learned_ch_train.py uses ~6K samples; GBDT papers suggest 5K-10K is sufficient
   - What's unclear: Minimum samples needed to generalize across graph types
   - Recommendation: Start with 5K samples from 4-5 graph types. If validation R² < 0.3, increase to 10K samples

3. **Model selection criteria during deployment**
   - What we know: Must fallback to degree-based if ML underperforms
   - What's unclear: How to detect underperformance at runtime without expensive queries
   - Recommendation: Pre-compute "expected benefit" during validation. At runtime, if graph features (avg degree, clustering) are outside training distribution, use degree-based
