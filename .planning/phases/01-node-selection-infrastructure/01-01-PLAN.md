2. Create NodeSelector dataclass:
   - Constructor takes graph: Graph parameter
   - Private _degree_cache: Dict[int, int] field with default_factory=dict
   - Follow codebase conventions: PascalCase class, snake_case methods

3. Implement degree() method:
   - Takes node: int parameter
   - Returns int (total degree = out_degree + in_degree)
   - Caches result in _degree_cache before returning
   - Uses graph.out_degree(node) for O(1) out-degree
   - Uses graph.in_degree(node) for in-degree (O(m) per call, so caching critical)

4. Implement out_degree() method:
   - Takes node: int parameter
   - Returns graph.out_degree(node) directly (O(1), no caching needed)

5. Implement in_degree() method:
   - Takes node: int parameter
   - Returns graph.in_degree(node) directly
   - Consider: Could cache this too since it's expensive, but degree() already caches total

6. Implement clear_cache() method:
   - Clears _degree_cache dict
   - Important: Call after graph modifications

7. Add comprehensive docstrings:
   - Module-level docstring explaining purpose
   - Class docstring explaining degree computation strategy
   - Method docstrings with time complexity notes

Follow research recommendations from 01-RESEARCH.md:
- Use total degree (out + in) as default degree metric
- Cache degree computations to avoid redundant work
- Provide clear_cache() for manual invalidation
- Don't auto-invalidate (keep it simple per research)

Match codebase style from CONVENTIONS.md:
- Type hints on all signatures
- snake_case methods
- Private attrs with _ prefix
- Descriptive docstrings
